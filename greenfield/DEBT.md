# 绿地欠账台账

已知的、决定推迟的事。每条记清楚**为什么当时没做**,以及**什么会迫使它必须做**。

这份台账只管绿地(`greenfield/` 与 `src/`)。`.scratch/` 里的是旧世界的议题,
与本分支无关。

规矩:一条欠账进这里,而不是留在某个人的记忆里或某条注释里;一条欠账被还掉,
就从这里删掉并在对应切片的修订记录里留痕。

## 记录完整性

### D-01 副作用与记录之间的缺口(已知限制)

进程若死在 git 提交与账本追加之间,仓库里会留下账本没有的提交。
见 [02-git-receipt §8.2](slices/02-git-receipt.md)。

- **为什么没做**:git 提交先于任何关于它的记录存在,两者不在一个原子边界内。
  调整顺序消不掉,只能靠事后对账。
- **可能的出路**:启动时把 HEAD 与最后一条收据比对,差额记为一条恢复记录。
  需要新动词(近似 `recover-tail` 之于日志尾部)与新场景。
- **什么会迫使它**:真实使用中出现过一次账本否认的提交。

### D-02 锁内幂等复检未被测试

`receipt` 在 `git_index` 锁内的第二次幂等检查没有测试覆盖。
见 [02-git-receipt §8.2](slices/02-git-receipt.md) 第 2 条。

- **为什么没做**:要同时具备"两调用交错"与"其间工作树又变了",测试无法确定性
  构造。加了进程屏障后仍撞不上——因为"为已有提交作证"这条路径把竞态吸收了。
- **什么会迫使它**:出现能确定性触发的注入点(例如给 `takeReceipt` 加相位钩子,
  与切片 1 崩溃矩阵同一手法)。那时这条应当立刻补上。

### D-03 运行时被 SIGKILL 时判据进程组成孤儿

见 [02-single-loop §6](slices/02-single-loop.md)。

- **为什么没做**:需要把判据 pid 持久化,才能在重启后收割。
- **什么会迫使它**:长跑判据在真实使用中留下过孤儿进程。

## 语义

### D-04 SL-13:amend 未显式标记既往 judgment 陈旧

目前只靠 progress signature 漂移隐式生效,没有显式标记。
见 [02-single-loop §6](slices/02-single-loop.md)。

- **为什么没做**:隐式路径在当前场景下行为正确,显式标记要新增记录种类。
- **什么会迫使它**:出现一个 amend 后 signature 恰好不变的情形。

## 发行

### D-05 安装器(HF-06)

幂等安装 skill 资产、版本化激活、不碰宿主任何配置。
见 [04-host-face §10](slices/04-host-face.md)。

- **为什么没做**:M1 之后它只剩"安装 skill 资产"这一半,而绿地**还没有定义发行
  形态**——没有 release 的概念,就没有"版本化激活"可言。先定发行形态,再谈安装。
- **什么会迫使它**:决定把运行时分发给自己以外的宿主。

### D-06 fs receipt 适配器

设计稿的领域模型写了"非 git: 文件 digest 集",实现里没有。

- **为什么没做**:FS 族保留场景没有一条需要它(要它的 FS-08 随 M1 出局)。
  没有场景要的东西不做。
- **什么会迫使它**:出现一个需要 fs 循环出具制品证据的场景。

## 已裁决为"不做"(不是欠账,列此以免重复讨论)

- **经 `receipt` 取得参与资格**:不改。运行时不是访问控制层,谁被允许调用什么
  是宿主的事;`observe` 一样不要求先有资格。裁决与 flip 条件见
  [02-git-receipt §8.3](slices/02-git-receipt.md)。
