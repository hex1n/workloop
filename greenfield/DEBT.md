# 绿地欠账台账

已知的、决定推迟的事。每条记清楚**为什么当时没做**,以及**什么会迫使它必须做**。

这份台账只管绿地(`greenfield/` 与 `src/`)。`.scratch/` 里的是旧世界的议题,
与本分支无关。

规矩:一条欠账进这里,而不是留在某个人的记忆里或某条注释里;一条欠账被还掉,
就从这里删掉并在对应切片的修订记录里留痕。

## 记录完整性

### D-01 副作用与记录之间的缺口(已收窄;剩余部分是设计接受的)

进程若死在 git 提交与账本追加之间,仓库里会留下账本没有的提交。**这个窗口关不掉**
——git 提交先于任何关于它的记录存在,两者不在一个原子边界内。

已做([09-reconciliation](slices/09-reconciliation.md)):提交带 trailer 记下它属于
哪个循环、由哪条命令产生,`status` 因此能**逐个指名**账本否认的提交;同 command id
重跑 `receipt` 会为那个提交作证并落账,缺口就补上。

**剩余**:修复仍然是人的事。自动修复要动 git 历史(revert / amend / reset),那是
执行,归宿主(宿主契约)。**能被发现,和被自动修复,是两件事,而前者才是本分。**

- **什么会迫使它改变**:出现一个运行时有权改写历史的场景——那同时要求修订宿主契约。

## 语义

### D-07 WT-09:只读校验既有 worktree 的 branch 与 base

见 [06-worktrees §6](slices/06-worktrees.md)。

- **为什么没做**:**没有任何动词会选择一个 worktree**。运行时不创建工作树、不切
  分支(M4:那是执行),宿主把工作区交给它。这条校验因此没有调用者,而没有写入者
  的机制正是审计花时间清掉的那一类。
- **前提复核(2026-07-25)**:公开动词表里没有任何一个接受 worktree 或分支;
  `--root` 是工作区路径,不是 worktree 选择器。前提仍然成立。
- **什么会迫使它**:出现一个接受 worktree 作为参数的动词。届时这条校验必须同时到位。

## 已裁决为"不做"(不是欠账,列此以免重复讨论)

- **安装器(原 D-05,连带 HF-06 / WN-06)**:**没有要安装的东西**。运行时是一个
  零依赖的 Node 包,`package.json` 里一个 `bin`;分发是 npm/tarball,幂等与版本化
  激活由 npm 负责。HF-06 改写后剩下的不变式"宿主配置字节不变"**由构造成立**——
  没有代码去读或写它;WN-06 的安装锁同理不存在。仍在验的是发行物装完能不能用:
  CI 里 `npm pack` + 全局安装 + 跑 `workloop --help`,三平台。
  **Flip 条件**:出现必须落在宿主机器上、且 npm 装不了的资产。见
  [10-closeout §3](slices/10-closeout.md)。
- **判据孤儿的最后一段(原 D-03 的剩余)**:运行时被强杀、而此后**再没有人碰这个
  循环**,那个进程组无人收割。与 D-01 同形:能被发现、能被收拾,但要有人再来一次。
  见 [10-closeout §2](slices/10-closeout.md)。
- **经 `receipt` 取得参与资格**:不改。运行时不是访问控制层,谁被允许调用什么
  是宿主的事;`observe` 一样不要求先有资格。裁决与 flip 条件见
  [02-git-receipt §8.3](slices/02-git-receipt.md)。
