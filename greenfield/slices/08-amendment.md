## 1. 缺陷的实际形状

`amend` 换掉判据与目标之后,实测:

```
goal      : 新目标
criterion : 375de250 (新的)
feedback  : {"verdict":"unsatisfied","failures":[{"id":"old-rule-violated"}]}
```

指令是 `repair`,而它附的证据是**对一条已经不存在的规则的裁决**。一个照着做的
agent 会去修一个不再被要求的东西。`status` 里那一轮也没有任何标记——读日志的人
看不出它属于修订之前。

此前的说法是"靠 progress signature 漂移隐式生效"。那句话只对了一半:signature
含判据 digest,所以**换判据**确实会让 stuck 计数归零;但**只改目标**不会,而且
无论哪种,**指令仍然把旧裁决当成当前的反馈递出去**。

## 2. 什么使一轮判断失效

**改变了判准或目标的修订**,使它之前的所有轮次失效。

- **判据变了** → 那些裁决是对另一把尺子量出来的;
- **目标变了** → 那些裁决回答的是另一个问题。
- **预算变了 → 不失效。** 预算是"还允许花多少",不是"什么算完成"。一次判断不会
  因为额度变了就不再为真。

失效是**从日志推导**的,不新增记录:一轮的 seq 早于最后一次实质修订的 seq,它就
失效。`loop_amended` 已经带着 `reason` 与 `granted_by`,溯源是齐的。**能推导的事实
不复制一份**——两份会漂,而漂的那份没人发现。

## 3. 失效之后

| | |
| --- | --- |
| 指令的 `feedback` | **为 null**。拿一条对旧规则的裁决当反馈,比不给反馈更糟 |
| 最近一轮已失效时的决策 | `implement`——**当前的判准之下,还没有任何观测** |
| stuck 计数 | 跳过失效轮次:同一个失败在换尺子前后不是同一个失败 |
| 预算 | **照常计入**。那些轮次真的花掉了,修订不退款 |
| `status` 的每一轮 | 带 `stale` 标记,读日志的人一眼看得见 |

"预算照常计入"这一条需要说明:失效的是**判断**,不是**发生过**。一个人可以用
`amend` 加预算,那是显式的决定;让修订自动退还额度,等于给了一条绕过预算的暗门。

## 3.1 快照必须带上写它的那个 reducer 的身份〔评审后补〕

给投影加一个字段,立刻造出一个**升级即失效**的缺陷,已实测:

```
正常读:   implement | feedback: null
旧快照读: repair    | feedback: 旧裁决又回来了
```

一份**上一版运行时写下的、digest 完全自洽的**快照不认识新字段,`round.seq <
undefined` 恒为假,于是所有失效的轮次**复活**,指令又开始递旧规则的裁决。**没有
任何错误,没有任何提示。**

这不是这个字段的问题,是**投影的形状变了而快照没有世代标记**。裁决:

- 快照写入时**盖上写它的 reducer 的身份**;读取时不匹配就跳过。
- 跳过是便宜的——快照是可弃缓存,日志才是真相(切片 1 已定的性质,这里正好用上)。
- 身份用常量 `PROJECTION_SHAPE`,而 `tests/store-snapshot.test.mjs` 里一条门禁
  **拒绝一次没有同时更新它的投影改动**。忘记是这类机制唯一真实的失效方式,所以
  它不能只靠自觉。

## 4. 不做

- **新增 `judgment_invalidated` 记录**:见 §2,可推导的事实不落第二份。
- **失效轮次从 `rounds` 里移除**:它们发生过。历史不因为不再适用就消失。
