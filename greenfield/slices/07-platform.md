## 1. 写规格前先找到了一个缺陷

`src/domain/graph.mjs` 的跨循环重叠判断硬写了 `/`:

```js
left.startsWith(`${right}/`) || right.startsWith(`${left}/`)
```

而 claim 的身份由 `claimIdentity` 构造,用的是 `path.sep`——**Windows 上是 `\`**。
于是循环 A claim `src`、循环 B claim `src\nested`,`"src\\nested".startsWith("src/")`
为假,**两个循环拥有互相包含的路径而无人拦下**。CC-02 的不变式在 Windows 上是坏的。

CI 一直在 windows-2025 上跑,没抓到,因为现有的 CC-02 测试只覆盖了**相等**与 `.`
两种重叠——**相等在任何分隔符下都成立**。嵌套那一支从来没在 Windows 上被执行过。

顺带一记:`src/domain/receipt.mjs` 里两处形似的比较**是对的**,因为它们比的是 git
的路径,而 git 无论平台一律用 `/`。看起来一样的两段代码,正确性依据完全不同——
这正是"重复代码"这个气味真正危险的地方:**复制时对的那份和错的那份长得一模一样**。

裁决:路径包含判断只保留一份,放在 `site.mjs`(路径语义归它),按 `path.sep` 比较;
git 路径的比较保持独立并注明它为什么用 `/`。

## 2. 路径变体(WN-02)

不变式:**路径里有什么字符,不改变任何语义**。

- 含空格与 CJK 的根:开单、观测、收据、重放全流程可用;
- 创建与快照过程**不留下中间文件**(`.partial` 之类);
- win32:盘符大小写变体等价(引用 CC-03 的物理身份);junction 作为目录别名等价
  (引用 WT-02)。

前两条在三平台都可测,后两条只在 win32 有意义——CI 在 windows-2025 上跑,所以
它们不是纸面断言。

## 3. 判据超时:树杀与它的降级路径(WN-04)

POSIX 侧已定版(切片 2 §4):spawn 时 `detached`,超时杀负 pid,即整个进程组。
SL-09 用一个真的孙子进程压着它。

win32 没有进程组。机制是 `taskkill /pid N /T /F`。

### 3.1 降级路径能做到什么,不能做到什么〔本切片定版〕

场景要求"首次树杀失败后,降级路径仍在限时内消灭父进程与孙进程"。**诚实地说,
第二句做不到全部**:

- `taskkill` 失败最常见的原因是进程已经没了——此时无事可做,也无需做;
- 若 `taskkill` 本身不可用(PATH 被剥离),Node 没有任何内建手段触达孙进程。
  Windows 上等价于进程组的东西是 **job object**,而 Node 不暴露它。

裁决:降级路径**先重试一次树杀**(瞬时失败是常见情形),再退到杀直接子进程;
并且**在执行记录里说明孙进程可能存活**,而不是假装树死了。

**"限时内返回"是可以保证的,并且必须保证**——超时的意义就是不挂死。这一条不打折。

**Flip 条件**:出现可用的 job object 绑定(原生模块或 Node 新 API),降级路径
应当改为绑定作业对象,这条限制随之消失。

## 4. 判据租约(WN-05)

"持有者 pid 已死但 deadline 未到 → 不抢占;deadline 已过 → 回收。"

机制在切片 1 已定版并已测(`locks.test.mjs`),而且**与锁类无关**——本切片补上
判据锁那一类的断言,因为一条只在别的锁类上被证过的性质,不能算这一类也被证过。

语义平台无关,但**进程存活探测在 win32 上语义不同**,所以这条必须在 Windows CI 上
真的跑,而不只是在开发机上绿。

## 5. WN-01 与 WN-06 不做

两条都以安装器为前提(三壳可调用、安装锁收割),而安装器已挂 D-05:绿地还没有
定义发行形态。它们随 D-05 一并回来。
