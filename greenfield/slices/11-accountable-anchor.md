之后暴露的三件事。

## 0. 根问题

判据是这个运行时**唯一的信任锚**——公理 2 的全部意义就是把 agent 的说法换成
运行时亲眼所见的事实。而这个锚同时是:

- **最不被保全的**:判据说出的结构算完签名就扔,只留一段散文;
- **最不可观测的**:想看运行时看到了什么,只能花掉一轮预算;
- **运行时自己承认验不了的**:它识破自相矛盾,识不破一贯说谎。

**锚是整个系统里最不可追责的那一部分。** 下面四步都从这一句来。

## 1. 签名必须能从日志重算(公理 1)

`progress_signature = H(criterion digest + artifact checkpoint + receipt digest +
规范化失败标识)`。前三样在日志里,**第四样没有**。

于是日志扛着一个**它自己解释不了的值**:读得到,验不了,也回答不了"第 1 轮到底
哪条检查失败了"。公理 1 说"重放即真相",而这个字段上它没有兑现。

裁决:`round_observed` 增加 `failures`,存的**正是喂给签名的那份标识**。

- **只存 id,不存 `expected`/`actual`**:后两者是判据关于某一刻的散文,已经在
  summary 里;日志欠的是**它所携带的那个 digest 的输入**。
- **界与判据读取器同源**:`MAX_FAILURES`/`MAX_FAILURE_ID` 移到声明字段的地方,
  判据读取器反向取用。**两个必须一致却分居的数字,总有一天会不一致**,而输的那
  一半是"判据已经跑完了,记录却写不进去"。
- **老记录显式为空**:`payload.failures ?? []`。已在日志里的记录永不重写,所以
  这个缺席是**永久的**,必须是读者能处理的值,而不是绊倒他们的那个。

随之:指令的 `feedback.failures`、`status` 每一轮的 `failures`。

### 1.1 为什么不是"让宿主自己从 summary 里解析"

那正是今天的状况,而它要求**下游重做一遍运行时已经做过的解析**。更要紧的是:
它救不了日志——`status` 与 `log` 仍然回答不了"哪条失败了",而那是账本的本分。

### 1.2 这不违反"能推导的事实不复制一份"

切片 8 立的规矩是不落第二份**可推导**的事实。这里正相反:**它推导不出来**,
原始结构已经没了。签名是它的单向摘要,不是它的替代。

### 1.3 快照世代

投影形状变了 → `PROJECTION_SHAPE` 从 `loop-state-2` 到 `loop-state-3`。
`tests/store-snapshot.test.mjs` 那道门禁按设计拦下了这次改动并要求换代。

## 2. `workloop try`:免费看见运行时看见的

**新增一个只读动词**,照 `observe` 的方式跑一次判据——工作目录设为工作区、
超时、杀整个进程组、只留输出尾部、算 digest——**打印它读出的 verdict 与 failures,
零记录零字节**。

- **为什么必要**:运行时验不了判据,那就必须让宿主能**便宜地**验。今天唯一的
  办法是花掉一轮;而第一次真实使用里,作者的判据连着两次报 indeterminate
  (先是 `node --test src/` 把目录当模块,再是解析格式与 reporter 不符)。
- **为什么不是"自己手跑一遍判据"**:手跑复现不了运行时的条件——工作目录、
  超时、进程组、输出截断窗口。**手跑绿而运行时红,是最难查的那种红。**
- **不需要循环**:`--root` + `--criterion` 就够。给了 `--loop` 时用该循环钉住的
  判据 digest 比对,不一致就说出来。
- **必须进只读动词集**,受 LK-11(只读动词零持久化字节变化)那条测试管辖。

**完成判据**:`try` 在一个尚未修复的仓库上打印 `unsatisfied` 与非空 failures,
且 store 目录逐字节不变。

## 3. indeterminate 与预算:裁决为照常计入

**照常扣。** 那一轮真的启动了判据、真的花了时间;退款等于开一条绕过预算的暗门
(与切片 8 拒绝"修订退款"同一个理由)。

**但这条只有在 §2 之后才站得住**:先给一条不花钱的调试路径,再说"调试你自己的
工具要花预算"才公平。**顺序本身是裁决的一部分**,所以两者同切片。

## 4. 两条人机工程

- `--loop` 收**唯一前缀**(像 git),歧义即拒绝(fail closed)。
- `--version`:装好的那份今天说不出自己是哪一版。

### 4.1 缩写止步于壳〔实现期修订〕

初版把前缀解析放进了 `loopOf`,那样每个调用方都能用缩写。**实现时发现这会破掉
公理 4。**

`amend`、`abandon`、`receipt`、`observe` 都用 loop id 算 `requestDigest`。缩写进去,
**同一条命令换个写法就成了另一条命令**——重试会被 P4 当成"同 command id 不同请求"
拒掉。而每个写动词还都用调用方传进来的字符串构造 payload,于是**缩写会直接进日志**。

裁决:**缩写是终端的便利,不是领域概念。** 解析成为一个领域函数 `resolveLoopId`,
但由壳在边界上**调用一次**;`loopOf` 仍然只认完整 digest。于是下游的 payload、
requestDigest、记录**由构造只见过完整 digest**。

这条是被测试逼出来的:遍历日志断言"没有任何记录带着被打出来的那串"时,`amend`
的派发漏掉了解析后的值——**保证来自测试,不来自我的仔细**。

## 5. 不做

- **不新增记录种类**:`failures` 属于那一轮的观测,不是另一件事。
- **不动判据协议**:`WORKLOOP_VERDICT` 那行一个字不改。
- **不发布**:`private` 与版本号是另一个决定,与本切片无关。

## 7. 工作流文本变回一个 skill〔实现期追加〕

绿地把旧世界的 3 个 skill(judgmentloop / meta-loop / workloop,共 210 行)一起删了,
内容以 `WORKFLOW.md` 的形式活了下来(214 行,而且被 HF-09 的门禁逐步压着)。
**但没有人会读它**:没有 frontmatter,agent 不会发现它;没有落到宿主的 skill 根下,
它只是 tarball 里的一份文档。**文本在发行物里,而它唯一的读者够不着。**

裁决:`greenfield/WORKFLOW.md` → `skills/workloop/SKILL.md`,加上 frontmatter。

- **只有一个 skill**。旧的 3 个里有 2 个服务于旧世界的多目标授权模型,新运行时
  没有那个概念;把它们复活等于把已删的语义偷渡回来。
- **搬,不复制**。一份文本两处副本必然漂,而漂的那份没人发现。
- **不重开安装器**。这里区分的是两件被混为一谈的事:**"能被 agent 加载"是一段
  frontmatter,"替你管理宿主资产"才是安装器**。前者本切片给,后者仍归 D-05。
  落地是宿主自己 `ln -s` 一次——**运行时不碰宿主的目录**,与 HF-06 那条不变式一致。
- **门禁**:frontmatter 必须在、`name` 必须等于所在目录名(不等就解析不到,而且
  不会说为什么)、description 必须实质且点名 workloop。`files` 改为 `skills`,
  HF-08 的发行物边界随之。

**D-05 的 flip 条件如何理解**:它说的是"出现必须落在宿主机器上、且 npm 装不了的
资产"。一个 skill 确实是那样的资产——**但它只对"谁来放"成立,不对"谁来做"成立**。
本切片让运行时把 skill **发出来**,放到哪里仍是宿主的动作,所以 D-05 维持不做。
真正会翻它的是:出现宿主**无法自己放置**、必须由运行时代劳的资产。
