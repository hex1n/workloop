## 1. 起点:一个已经存在的缺陷

设计稿说 claims 的唯一理由是让两个循环的意图不重叠,从而 **receipt 能界定
"我的路径"**。当前实现把 claim 当**字面字符串**比较,于是:

```
loop A claims  Src      → 接受
loop B claims  src      → 接受   ← 同一个目录(macOS / Windows 默认大小写不敏感)
loop C claims  link     → 接受   ← link 是指向 Src 的符号链接,同一个目录
```

已实测复现。**两个循环因此可以拥有同一批文件**,各自出具互相矛盾的 receipt——
claims 存在的唯一理由被绕过了,而绕过它只需要按一下 Shift。

## 2. claim 的身份是它的物理身份

裁决:**claim 记录并比较的是物理路径**,不是调用方写下的字符串。

```
claim 字符串 → 规范化 → 解析到最深的已存在祖先(realpath) → 接回不存在的尾巴
             → 相对于 root 的 realpath 表达 → 这就是身份
```

一次解析同时关掉两类别名:

- **符号链接**:`realpath` 就是它的定义;
- **大小写**:`realpathSync.native` 在大小写不敏感的卷上返回**磁盘上的真实拼写**,
  于是 `src` 与 `Src` 归一到同一个身份。

  **必须是 `.native`**〔实现期修订〕。Node 的 JS 实现 `fs.realpathSync` 解析符号
  链接、但原样返回调用方给的拼写;只有平台调用会报告磁盘上的拼写。两者的差别就是
  CC-03 的全部——用错那个,`src` 与 `Src` 仍是两个身份,两个循环仍能拥有同一批
  文件。这条是实现时被红测试逼出来的:规格初稿只写了"realpath",而当时代码里的
  helper 用的正是不归一的那个。

### 2.1 大小写敏感性是卷的性质,不是平台的性质〔本切片定版〕

场景原文写"win32/darwin 上大小写变体重叠拒绝(linux 放行)"。**按平台判是错的**:
macOS 可以有大小写敏感的卷,Linux 可以挂载不敏感的文件系统,而 Windows 有
`FILE_ATTRIBUTE_CASE_SENSITIVE_DIR`。

按语料 README 的规则,平台名是**旧值锚**,语义不变式是"物理身份闭合别名"。所以
**探测,不假设**:身份由 `realpath` 给出,而 `realpath` 本来就说的是这个卷的实话。
不需要单独一条"这是什么平台"的判断——那正是会判错的那种判断。

### 2.2 claim 不得经由别名逃出工作区

解析之后必须重新检查:身份仍在 root 之内。否则一个指向 `/etc` 的符号链接可以让
claim 落在工作区之外,而 `assertClaims` 对**字符串**的 `..` 检查完全看不见它。

这条是解析带来的新义务;不解析时它以另一种方式存在(根本无法发现),不解析并不
更安全。

### 2.3 不存在的路径

claim 命名的是意图,第一轮时路径通常还不存在(切片 4 §3.2 已立此规矩)。做法:
解析到**最深的已存在祖先**,再把剩下的一段按字面接回去。于是:

- `src/new/feature`,而 `src` 存在 → 身份是 `<src 的真实拼写>/new/feature`;
- 尾巴部分的大小写无从归一,**这是事实而非缺陷**:那个目录还不存在,它将来叫什么
  拼写由创建它的人决定。这一点必须写下来,因为它是一个会让人以为"检查失效了"的
  性质。

### 2.4 `...` 不展开

字面目录名 `...` 是一个普通目录名,不是 `..` 的变体。`path.normalize` 不动它,
现有的 `..` 分段检查也不会误伤它。本切片只需**测住**它,不需要新机制。

## 3. 排序与 locale

claims 以 **code unit 序**排序(`Array.prototype.sort` 的默认行为),不使用
`localeCompare`。理由:排序结果进 digest。一个随机器语言环境改变的顺序会让**同一
组 claims 在两台机器上算出不同的 digest**,而 digest 是这个运行时用来判断"是不是
同一件事"的全部手段。

## 4. 会话只是溯源(CC-04)

审计改写后的断言,逐条对照实现:

| 断言 | 现状 |
| --- | --- |
| 一个会话可同时推进多个活动节点 | 成立(不存在任何按会话的路由) |
| 每条变更命令记录发起会话 | 成立 |
| 生命周期变更要求发起者是参与者 | 成立(SL-11) |
| 不存在"按会话猜节点"的路径 | 成立(寻址一律显式) |

**本切片对此不新增机制,只新增测试。** 一条没有测试压着的性质,和一条没有的性质
在下一次重构面前是一样的。

## 5. 一个 store 多个循环(CC-01)

切片 3 已经实现。本切片补齐它的查询面断言:两个不相交 claims 的 open 共享同一个
store,loop id 不同,`ready` 同时列出两者。

## 6. 影响面

- `openLoop` 新增必填 `root`。**claim 的身份是关于某个文件系统的事实,不知道是
  哪个文件系统就无从谈起**——现在的签名能在不知道 root 的情况下接受 claims,这本身
  就是缺陷的形状。
- `assertClaims(claims)` → `assertClaims(root, claims)`,返回身份。
- 跨循环重叠检查(`claimConflicts`)比较的是身份,不再是原始字符串。

## 6.1 身份跟的是文件系统,git 跟的是自己的记录〔评审后补〕

一处评审发现的、比缺陷本身更值得写下来的事:**同一条路径有两个权威。**

claim 的身份取自文件系统的真实拼写;而 receipt、漂移检测、祖先检查全都把这个
字符串当 **git pathspec** 用,而 git 的 pathspec 匹配**对 index/tree 是大小写
敏感的**,即使 `core.ignorecase=true`(已实测;`:(icase)` 又和 `:(exclude)` 一样
不被 `ls-tree` 支持)。

两者只在一种状态下分歧:目录被做了只改大小写的重命名,而 git 没被告知。此时
每一条 pathspec 都匹配不到东西,于是 **stage 了零个文件的 receipt 报告 `clean`**
——切片 2 §2 明令禁止的那件事,由一条我以为无关的改动造出来了。

裁决:**不去追病因,去堵形状**。规则是:

> claim 在磁盘上存在、却对本次操作零贡献 → 这是运行时无法解释的空,`uncertain`。

理由是这条规则**不依赖于我是否想到了那个病因**。同样形状的下一个病因会被同一条
规则接住。而"claim 命名的东西还不存在"是另一回事,仍然 `clean`——`live` 已经把
它排除在外了。

## 6.2 未创建路径的跨循环比较必须折叠大小写〔评审后修订〕

§2.3 说不存在的尾巴保留字面拼写,那是对的;但我据此让**跨循环比较**也用了字面
字符串,于是两个循环可以今天各自 claim `Src/new` 与 `src/new`,**明天其中一个把
目录建出来,两者就共享同一棵树了**——正是 claims 要防的事,只是推迟了一天。

身份保留字面拼写,**比较时折叠**。卷是否大小写敏感照旧探测(§2.1),只读探测,
不在用户的工作区里造探针目录。

## 6.3 循环不得 claim 控制面〔评审后补〕

控制面路径被排除在每一次 checkpoint 与 receipt 之外(FS-02)。于是一个 claim 了
`.git` 或账本目录的循环,**永远无法观测、也永远无法为自己的范围出具证据**——一个
不可能赢的循环,而且是无声地发下去的。开单时拒绝。

## 7. 不做

- **claim 的大小写归一化用于显示**:记录的是物理拼写,展示层不改写它。
- **跨 store 的 claim 冲突**:store 是账本边界,两个 store 的 claims 互不可见。
  这与"嵌套 store 双向拒绝"(切片 4 §4)是同一条边界的两面。
